1. Headline result — humanoid ground contact

bench_vbd_humanoid_contact.py — 90 steps, 3 iterations, fixed_high joint stiffness, ground contact. At high stiffness the local solve cannot hold the articulation together; the sparse solve keeps joint error near machine noise and runs faster.

  • Joint error: sparse reduces angular residual ~2760× (h1) and ~81× (g1); linear residual ~470× (h1) and ~27× (g1).
  • Stability: local shows large spurious body velocities (1.7–2.3 m/s) as stiff joints fight the solver; sparse stays effectively at rest.
  • Cost: sparse is ~1.6× faster despite the higher-quality solve.

Caveats

loop_fixed scenario does not run against the current tree. Every case fails in ModelBuilder.add_articulation with "Body 0 has multiple parents in this articulation … Loop-closing joints must not be part of an articulation." The builder now rejects loop-closing joints inside an articulation, but build_loop_fixed still adds them there. The main benchmark records these as available: false; the iteration sweep has no error guard, so it was run with chain_fixed / chain_revolute only.
  • bench_robot_perf.py (VBD-vs-MuJoCo throughput) is not part of this run — it is not referenced by the README commands and needs a MuJoCo-capable environment.
  • Absolute per-step times are CPU- and load-dependent; treat them as within-run relative comparisons, not portable absolutes.
  • Videos are ViewerGL, 960×540, rendered headless via Xvfb / software GL.
